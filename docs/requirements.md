## 捷需求文档

### **总体完成的定义**

任何一个用户故事，只有在满足以下所有条件时，才能被认为是“完成”：

1.  **代码质量**:
    *   代码已通过静态代码分析工具检查（如 ESLint, GoFmt）。
    *   代码已遵循项目既定的编码规范。
    *   代码已经过至少一位其他团队成员的 Review。
    *   代码中不包含 `TODO` 或 `FIXME` 等临时标记。
2.  **测试**:
    *   已编写并通过单元测试，核心逻辑测试覆盖率不低于 80%。
    *   已编写并通过集成测试（如果适用）。
    *   所有测试均能在持续集成（CI）环境中稳定通过。
3.  **文档**:
    *   API 接口已更新（如使用 Swagger/OpenAPI）。
    *   代码中的关键逻辑有必要的注释。
4.  **部署与验收**:
    *   代码已合并到主开发分支（如 `develop`）。
    *   功能已成功部署到预发布环境。
    *   产品负责人已根据下方的“验收标准”对功能进行验收，并确认通过。

### **Sprint 1: MVP - 核心用户流程**

**Sprint 目标**: 实现新用户从注册到成功收藏并查看第一个仓库的完整核心流程。

#### **用户故事 1: 用户注册**

-   **作为** 一个新用户，
-   **我想要** 通过提供用户名和密码来创建一个新账户，
-   **以便** 我可以开始使用 RepoVault 来收藏仓库。

**验收标准**:

-   **场景 1: 成功注册**
    -   **Given** 我在注册页面，
    -   **When** 我输入一个未被使用的、有效的用户名和符合要求的密码，
    -   **And** 我点击“注册”按钮，
    -   **Then** 系统应创建新用户，
    -   **And** 页面应跳转到登录页面，
    -   **And** 我应看到“注册成功，请登录”的提示信息。
-   **场景 2: 用户名已存在**
    -   **Given** 我在注册页面，
    -   **When** 我输入一个已被注册的用户名，
    -   **And** 我点击“注册”按钮，
    -   **Then** 系统应阻止注册，
    -   **And** 我应在用户名输入框下方看到“用户名已存在”的错误提示。
-   **场景 3: 输入无效信息**
    -   **Given** 我在注册页面，
    -   **When** 我输入不符合格式要求的用户名（如太短）或密码（如太短），
    -   **And** 我点击“注册”按钮，
    -   **Then** 系统应阻止注册，
    -   **And** 我应在相应输入框下方看到具体的格式错误提示。
-   **安全要求**: 密码在存储到数据库前必须经过加盐哈希处理。

---

#### **用户故事 2: 用户登录**

-   **作为** 一个已注册用户，
-   **我想要** 使用我的用户名和密码登录系统，
-   **以便** 我可以访问和管理我的个人收藏夹。

**验收标准**:

-   **场景 1: 成功登录**
    -   **Given** 我在登录页面，
    -   **When** 我输入正确的用户名和密码，
    -   **And** 我点击“登录”按钮，
    -   **Then** 系统应验证我的身份，
    -   **And** 页面应跳转到我的主面板（收藏夹列表页），
    -   **And** 我应收到一个有效的认证令牌。
-   **场景 2: 凭据错误**
    -   **Given** 我在登录页面，
    -   **When** 我输入了错误的用户名或密码，
    -   **And** 我点击“登录”按钮，
    -   **Then** 系统应阻止登录，
    -   **And** 我应看到“用户名或密码错误”的提示信息。
-   **场景 3: 访问受保护页面**
    -   **Given** 我未登录，
    -   **When** 我尝试直接访问收藏夹列表页，
    -   **Then** 系统应将我重定向到登录页面。

---

#### **用户故事 3: 添加第一个仓库**

-   **作为** 一个已登录用户，
-   **我想要** 通过输入一个 GitHub 仓库的 URL 来收藏它，
-   **以便** 我能将它加入我的知识库。

**验收标准**:

-   **场景 1: 成功添加新仓库**
    -   **Given** 我已登录并处于主面板，
    -   **When** 我在输入框中粘贴一个有效的、公开的 GitHub 仓库 URL（如 `https://github.com/facebook/react`），
    -   **And** 我点击“添加”按钮，
    -   **Then** 系统应从 GitHub API 获取该仓库的名称、描述、语言和星标数，
    -   **And** 该仓库应出现在我的收藏列表顶部，
    -   **And** 我应看到“添加成功”的提示。
-   **场景 2: 添加无效 URL**
    -   **Given** 我已登录并处于主面板，
    -   **When** 我输入一个无效的 URL 格式，
    -   **And** 我点击“添加”按钮，
    -   **Then** 系统应阻止添加，
    -   **And** 我应看到“请输入有效的 GitHub 仓库 URL”的错误提示。
-   **场景 3: 添加不存在的仓库**
    -   **Given** 我已登录并处于主面板，
    -   **When** 我输入一个格式正确但实际不存在的 GitHub 仓库 URL，
    -   **And** 我点击“添加”按钮，
    -   **Then** 系统应阻止添加，
    -   **And** 我应看到“未找到该 GitHub 仓库”的错误提示。
-   **场景 4: 重复收藏**
    -   **Given** 我已登录，
    -   **And** 我已经收藏了仓库 `A`，
    -   **When** 我再次尝试添加仓库 `A` 的 URL，
    -   **Then** 系统应阻止添加，
    -   **And** 我应看到“您已收藏过此仓库”的提示信息。

---

#### **用户故事 4: 查看我的收藏夹**

-   **作为** 一个已登录用户，
-   **我想要** 在一个清晰的列表中看到我收藏的所有仓库，
-   **以便** 我能快速浏览和回顾我的收藏。

**验收标准**:

-   **场景 1: 查看有内容的列表**
    -   **Given** 我已登录并收藏了至少一个仓库，
    -   **When** 我访问主面板，
    -   **Then** 我应看到一个仓库列表，
    -   **And** 每个列表项应显示：仓库名称（可点击跳转到 GitHub 原地址）、描述、主要语言、星标数。
    -   **And** 列表应按收藏时间倒序排列（最新的在最前面）。
-   **场景 2: 查看空列表**
    -   **Given** 我是一个新登录的用户，还未收藏任何仓库，
    -   **When** 我访问主面板，
    -   **Then** 我应看到一个友好的提示，例如“你还没有收藏任何仓库，快去添加一个吧！”。
